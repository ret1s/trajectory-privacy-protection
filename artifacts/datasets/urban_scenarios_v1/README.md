# Controlled urban scenario dataset v1

**Development data, not measured protection coverage.** This is separate from
`artifacts/benchmarks/paper_benchmark`, whose five-scenario results stay frozen.
Motion is generated by SUMO 1.27.1 on OSM only. No GeoLife input is used.

- `dataset.json`: **evaluator-only** bundle, including full trajectories and labels.
- `dataset.sha256`: checksum of that bundle.
- `summary.json`: counts, not privacy/utility scores.
- Detailed scenario recipes and limitations: `thesis/scenario_dataset_spec.tex`.

The release contains 36 completed sessions, 21,818 one-second FCD samples and
96 scenario records spanning all ten scenario families and 28 of 30 declared
subcases. Records reuse trips; the independence unit is the related route
family, of which there are only **three**. None of these counts is an attack
success rate, protection score or proof of privacy.

S1.C (rare POI context) and S6.C (routine/rare destinations across days) are
specified but not generated. S6.B, S8.A and S9.A occur in only one family and
do not support train/validation/test evaluation for each subcase yet.

## Inspect one case

```bash
venv/bin/python -m experiments.inspect_scenario_suite S5.C
venv/bin/python -m experiments.inspect_scenario_suite S4.B --evaluator
venv/bin/python -m experiments.inspect_scenario_suite S1.C
```

The first command shows bounded **local input**, not protected coordinates.
`device_view()` is the only supported pre-protection input adapter: it removes
identifiers, future coordinates, raw clock origin, route plan and labels.
S8 uses a common relative epoch to preserve timing between paired users;
other cases normalize per session. No hidden departure clock is disclosed.
Pass its output through a protection mechanism before giving anything to an
attacker. The full JSON is never an attacker-facing API. `reference_queries()`
only illustrates plaintext vs constant-category-cover controls for S7; it is
not a new privacy mechanism or the current BR-Dummy benchmark output.

S4 labels distinguish person/device **pairwise linkage**, not identification
among an enrolled population. S5 labels the next external edge, not a fixed
forecasting horizon. S8 separates synthetic companionship from measured
proximity, including a nearby non-companion negative. Endpoint labels are the
first/last recorded FCD samples, not houses, social identities, or exact
unsampled arrival positions. S9/S10 retain the full allowed route at 20 s
cadence rather than v2's fixed 220 s window.

## Reproduce and verify

Run at the repository root; the OSM extract must exist under `data/raw/` and
the official SUMO toolchain must be installed (see `data/README.md`).

```bash
venv/bin/python -m experiments.build_scenario_suite --output tmp/scenario_suite_replay --workdir cache/scenario_suite_replay
venv/bin/python -m experiments.verify_scenario_suite --dataset tmp/scenario_suite_replay/dataset.json --raw --reference artifacts/datasets/urban_scenarios_v1/dataset.json
venv/bin/python -m pytest -o addopts='' -q tests/test_scenario_suite.py
```

The generator refuses to replace an existing dataset unless `--replace` is
explicit. Prefer a fresh directory for replay. SUMO/XML and public OSM network
caches are ignored in Git; the tracked bundle keeps their hashes, tool
versions, commands, actual arrivals and scientific source hashes. After a fresh
clone, validate a rebuild's own raw caches and use `--reference` to compare it
to the tracked bundle. Original raw XML hashes cannot be reconstructed merely
by rerunning: XML comments include generation timestamps. The direct original
`--raw` audit requires its original caches, which are present on this workspace.

SUMO XML includes timestamps and paths, so raw hashes need not match between
runs. Compare scientific content (`traces`, `records`, `catalogue`, `summary`,
and each family's seed, design, split and actual vehicle attributes), not
runtime XML comments or provenance paths. The verifier checks all stored FCD
against raw XML, complete routes, lane progress, one-second continuity,
scheduled-stop evidence, resource assignment, observation cutoffs and gates.

Seeds 91/92/93 are development train/validation/test groups respectively, not
an untouched final-paper test set. The public map is shared. Add independent
families, balanced negatives and realistic activity/POI models before fitting
new attackers or making comparative performance claims on this suite.

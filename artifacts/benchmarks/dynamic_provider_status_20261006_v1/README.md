# Frozen-Q controlled dynamic provider-status diagnostic

The public workload/source were pinned before scoring. This uses the already-inspected SAME-MAP cohort: all 24 TEST families × 3 nested draws, all eight linked sessions, unchanged Geo-I public Q/clock/ledger, and fixed L20/L30. It is secondary workload sensitivity, not another independent confirmation or a tuned privacy result.

`protocol.json`, `status_world.json.gz`, `public_reply60.npz` and `source_snapshot/` pin the complete public fixture, public catalogue, 72 included blocks, source hashes and definitions. Availability is generated by a fixed hash of public POI ID, absolute public 60-second epoch and seed 2026100623, at probability .5. There are 418 public records and 88 observed epochs. Departure clocks are 0,1500,…,10500 seconds; epochs never reset to zero at a new session.

The provider contract returns **top-L STATIC nearest records per category, with current availability bits for those IDs**. It does not filter availability before selecting top-L. Protected requests always ask every public category, irrespective of the four private local purposes. Coordinates/destination truth are reused only by local evaluation; no additional GPS or sampler call is made.

| Arm | Current status known for | Local candidate rule |
|---|---|---|
| Geo-I L20/L30 current | IDs returned at this event | Current known-available records |
| Geo-I L20/L30 epoch60 | Causal union of returned IDs in current **absolute** public epoch | Static records may persist, status bits expire at epoch boundary |
| Raw L20/L30 | Static top-L response to saved true GPS, with current bits | Utility positive control, no location protection |
| Stale full catalogue, safe | Initial epoch0 bits only; later epochs unknown | Reject unknown/expired status |
| Current full-catalogue bulk oracle | Every public ID, refreshed once per observed epoch | Exact stronger API control; no location upload |
| Stale full catalogue, unsafe | Deliberately misuses expired epoch0 bits | **Invalid operational negative control**; false availability and unknown returned items counted |

Dynamic reference is top5 **currently available** POIs for each purpose/category. Empty reference is N/A, never 100%; no retrieved candidate when a reference exists is zero. Missing/unreceived IDs and received static records with unknown current status are separate. Operational arms never return unavailable or currently unknown POIs. Within-radius keeps the same private 1000m radius; detour keeps the same evaluator-only destination; fastest travel retains public static road speeds. This is dynamic availability, not a dynamic-traffic/price study.

The seed/full status fixture are public in this research artifact for reproducibility, but excluded from the controlled client interface. A client given the fixture can compute statuses locally. This diagnostic therefore tests freshness/dataflow under the assumed provider API; it does **not** establish unpredictable real availability or the necessity of a remote server. If a provider permits current full-catalogue bulk status, that control must remain exact and superior. Four purposes are a workload aggregate, not four independent replications; all families/draws share this one pinned world.

Cost is synthetic compact JSON application payload only. Metadata and status upload/download bytes are reported separately; no real bandwidth, HTTP/TLS, latency or battery claim. Bulk cost includes one static catalogue prefetch and one status request/download per observed epoch. Full-catalogue oracle is a distinct, stronger API than a location-based top-L provider.

`readout.json` uses `summary[arm][all|cold|temporal_tail_400_600][purpose]`, with equal-family/equal-nested-draw means, per-family values, per-draw means and explicit all-event/category denominators. `equal_purpose_macro` is separate. `cost[arm]` contains request counts, metadata request/reply bytes and status upload/download bytes. Each compressed `blocks/` file retains every event/purpose metric without duplicating original GPS/Q/reply lists, plus their source hashes and unchanged-tape certificate.

L30 remains the previously frozen depth. Under this new availability workload its current-only gain over L20 is 3.59 percentage points, paid for with 30.37% more application JSON bytes. Causal epoch60 accumulation adds 0.52 points at L20 and 0.34 points at L30 without new requests or bytes. It cannot reuse expired status: previously received static IDs alone do not establish current availability. Maximum static cache storage is 418 records.

The L30 current-only purpose means are 93.74% nearest, 93.74% fastest, 84.77% within-radius and 93.50% detour. Radius has 16,557 defined events out of 18,114, because its reference can be empty; the other purposes have 18,114 defined events. Across all four purposes, 324,153 category/event cells have nonempty references and 110,583 are empty/N/A. Empty cells are retained in the denominators rather than awarded perfect scores.

Every operational arm returned **zero unavailable and zero current-status-unknown items**. The safe stale-catalogue control loses coverage because expired status becomes unknown, not because those POIs are known to be unavailable. The unsafe control returned 1,279,509 items across purposes, including 623,325 currently unavailable items and 1,264,314 items whose current status was unknown to that client. These counts overlap; its 50.49% Recall cannot be treated as a valid live answer.

Current full-catalogue bulk remains a dominating control: it answers exactly with no location upload and about one eighth of the protected L30 JSON bytes. Consequently, this controlled dynamic result does **not** resolve the small-catalogue/bulk-download application gap. A real remote-service claim needs a provider contract and workload that preclude free current bulk access or local status reconstruction. No dynamic traffic, independent status worlds, live provider, latency, battery, new attacker or privacy result was measured here.

The three nested-draw current-only macro means are L20 87.68/88.14/87.73% and L30 91.17/91.75/91.39%. These describe protected-stream variation conditional on the same fixed synthetic status world; they are not three independent availability worlds. Per-family/draw/purpose values, event/category partitions, cost fragments and source hashes remain in [readout.json](readout.json) and the 72 compressed block files.
